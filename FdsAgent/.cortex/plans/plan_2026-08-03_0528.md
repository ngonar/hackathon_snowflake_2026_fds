## Implementation Steps

### 1. Create Snowflake table + stream + task (SQL)

Create the infrastructure in Snowflake:

```sql
-- Table where new transactions land (replaces RabbitMQ publish)
CREATE TABLE IF NOT EXISTS pending_transactions (
    id INT AUTOINCREMENT,
    txn_id INT,
    reference_number TEXT,
    sender_id INT,
    recipient_id INT,
    source_currency TEXT,
    target_currency TEXT,
    source_amount FLOAT,
    target_amount FLOAT,
    exchange_rate FLOAT,
    fee FLOAT,
    status TEXT,
    created_at TIMESTAMP_NTZ DEFAULT CURRENT_TIMESTAMP(),
    processed BOOLEAN DEFAULT FALSE
);

-- Stream to track new inserts
CREATE STREAM IF NOT EXISTS pending_transactions_stream 
    ON TABLE pending_transactions
    APPEND_ONLY = TRUE;

-- Task that fires when stream has data, marks rows as processed
CREATE TASK IF NOT EXISTS process_pending_transactions
    WAREHOUSE = 'SNOWFLAKE_LEARNING_WH'
    SCHEDULE = '1 MINUTE'
    WHEN SYSTEM$STREAM_HAS_DATA('pending_transactions_stream')
AS
    UPDATE pending_transactions 
    SET processed = TRUE 
    WHERE id IN (SELECT id FROM pending_transactions_stream);
```

> Note: The task marks rows as "ready to process". The actual fraud analysis still runs in Python (because enrichment data is in SQLite and the MCP update call is Python-based).

### 2. Rewrite `consumer.py` → `consumer.py` (Snowflake Stream poller)

Replace the RabbitMQ consumer with a background thread that polls the Snowflake stream for unprocessed transactions:

- Connect to Snowflake (reuse existing creds from `.env`)
- Poll every few seconds: `SELECT * FROM pending_transactions WHERE processed = FALSE`
- For each new row, invoke `fds_process_chain.ainvoke(txn_data)`
- Mark the row as processed: `UPDATE pending_transactions SET processed = TRUE WHERE id = ?`
