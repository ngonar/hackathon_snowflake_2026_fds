## Context

The app has a split-brain data problem:
- **API Server** stores all operational data (users, recipients, transactions) in a local SQLite file inside the container
- **`queue.py`** tries to write transactions to Snowflake's `PENDING_TRANSACTIONS` but uses `SNOWFLAKE_PASSWORD` auth (empty) → silently fails
- **FDS Agent** reads `USERS`, `RECIPIENTS`, `TRANSACTIONS` from Snowflake for enrichment → gets empty results, so fraud analysis has no context
- **FDS Agent** writes analysis to its own SQLite (`fds.db`), not to Snowflake's `FRAUD_ANALYSIS_LOG`
- Only `REMEDIATION_ACTIONS` gets populated (39 rows) because the agent uses SPCS OAuth for that write

## Implementation Steps

### 1. Fix `ApiServer/app/queue.py` — Use SPCS OAuth token
Same pattern as the `nl_query.py` fix: check for `/snowflake/session/token`, use OAuth if available, fall back to password for local dev.

### 2. Add Snowflake sync for USERS and RECIPIENTS in `queue.py`
Add two functions:
- `sync_user_to_snowflake(user_data: dict)` — upserts a user row into `SNOWFLAKE_LEARNING_DB.FDS.USERS`
- `sync_recipient_to_snowflake(recipient_data: dict)` — upserts a recipient into `SNOWFLAKE_LEARNING_DB.FDS.RECIPIENTS`

### 3. Call sync functions from API routers
- In `routers/auth.py` (register) and `routers/users.py` (KYC update, deposit) — call `sync_user_to_snowflake` as a background task
- In `routers/recipients.py` (create recipient) — call `sync_recipient_to_snowflake` as a background task

### 4. Add Snowflake write to FDS Agent's `agent.py`
After saving to local SQLite, also INSERT into `SNOWFLAKE_LEARNING_DB.FDS.FRAUD_ANALYSIS_LOG` (using the existing `_get_snowflake_session()` which already has OAuth support).

### 5. Also sync completed transactions to `TRANSACTIONS` table
In `queue.py` or via the FDS Agent after processing, write the transaction to the `TRANSACTIONS` table so enrichment queries have history.

### 6. Add `SNOWFLAKE_HOST` env var to `FdsAgent/spec.yaml`
Ensure the FDS Agent spec also has the `SNOWFLAKE_HOST` variable (it may already reference it but not define it).

### 7. Rebuild and push API server Docker image, restart service
