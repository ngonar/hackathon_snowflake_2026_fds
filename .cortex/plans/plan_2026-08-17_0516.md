## Context

Currently the FDS agent's only post-analysis action is calling `update_transaction_status` via MCP — a single status toggle. There's no autonomous remediation logic. The ApiServer already exposes wallet balance updates, KYC approval, and transaction status changes. The MCP server wraps all these as tools.

Key gaps:
- No wallet freeze mechanism exists (need new API endpoint + MCP tool + Snowflake audit table)
- No compliance audit log in Snowflake (only local SQLite `fds.db`)
- No automated KYC re-verification dispatch
- No risk-level-based orchestration (all decisions treated the same)

## Implementation Steps

### 1. Create new Snowflake tables for remediation

- `REMEDIATION_ACTIONS` — logs every automated action taken (freeze, alert, audit)
- `WALLET_FREEZE_LOG` — tracks frozen wallets with reason, timestamp, freeze duration
- `KYC_REVERIFICATION_QUEUE` — queue for users needing re-verification with priority

### 2. Create CoCo CLI skill: `fds-remediation`

**File**: `.cortex/skills/fds-remediation/SKILL.md`

Orchestrates multi-step remediation based on risk tier:
- **CRITICAL (score ≥ 85)**: Auto-freeze wallet + fail transaction + compliance audit + KYC re-verification alert
- **HIGH (score ≥ 65)**: Fail transaction + compliance audit + flag for manual review
- **MEDIUM (score ≥ 50)**: Mark suspicious + generate compliance record
- **LOW (score < 50)**: Auto-fund + standard audit log

Scripts:
- `scripts/freeze_wallet.sql` — Insert freeze record + update user wallet status
- `scripts/generate_compliance_audit.sql` — Insert structured compliance record with full evidence chain
- `scripts/dispatch_kyc_reverification.sql` — Queue user for KYC re-check with priority
- `scripts/execute_remediation.sql` — Master orchestration procedure that chains actions by risk tier

### 3. Create CoCo CLI skill: `fds-remediation-monitor`

**File**: `.cortex/skills/fds-remediation-monitor/SKILL.md`

Provides observability over remediation actions:
- Active wallet freezes and their duration
- KYC re-verification queue status
- Remediation action history and SLA compliance
- Unfreezing/escalation workflow

### 4. Add MCP tools for wallet freeze/unfreeze

Extend `McpServer/server.py` with:
- `freeze_user_wallet` — Calls admin API to zero-out wallet + set frozen flag
- `unfreeze_user_wallet` — Restores wallet access
- `dispatch_kyc_reverification` — Triggers KYC status reset to force re-submission

### 5. Extend ApiServer with freeze endpoint

Add to `ApiServer/app/routers/admin.py`:
- `POST /admin/users/{user_id}/freeze` — Freezes wallet, sets `kyc_status = 'FROZEN'`
- `POST /admin/users/{user_id}/unfreeze` — Restores wallet access

Add `FROZEN` to allowed KYC statuses in the User model.

### 6. Wire FdsAgent to execute remediation autonomously

Modify `FdsAgent/app/agent.py` to call the remediation chain after classification:
- After decision is determined, invoke `execute_remediation` via MCP tools based on risk tier
- Replace the single `update_transaction_status` call with the full remediation workflow
