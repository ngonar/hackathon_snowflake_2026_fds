## Integration Plan: Published Skills → FdsAgent Runtime

The core idea: have the FdsAgent **read SQL templates from the Cortex Extension stage at startup** and execute them at runtime. This means re-publishing a skill automatically updates the agent's behavior without rebuilding the Docker image.

### New Files

1. **`FdsAgent/app/skill_loader.py`** — Fetches SQL files from the Cortex Extension stage (`USER$NGARTOONIST.SKILL_SHARING.*`) at startup. Caches them in memory as a dict keyed by skill name + script name. Falls back to bundled SQL if the stage is unreachable.

2. **`FdsAgent/app/anomaly_detection.py`** — New module that runs the 5 anomaly detection scripts (velocity_check, time_evasion, smurfing_check, rapid_onboarding, circular_check) and computes the composite weighted anomaly score using the same weights defined in the skill SKILL.md.

### Modified Files

3. **`FdsAgent/app/enrichment.py`** — Replace the 4 basic `SELECT *` queries with the skill SQL scripts (sender_profile, sender_behavior, recipient_profile, recipient_inflow). These produce much richer behavioral profiles (avg amounts, std dev, frequency, account age, distinct sender/recipient counts, etc.).

4. **`FdsAgent/app/agent.py`** — Wire the new pipeline:
   - After enrichment, run anomaly detection (new step)
   - Feed enrichment + anomaly results into the LLM prompt (richer context)
   - Use the skill-based classification prompt structure from `classify_fraud.sql`
   - Use skill SQL for logging to `FRAUD_ANALYSIS_LOG` and `REMEDIATION_ACTIONS`

5. **`FdsAgent/app/server.py`** — Initialize skill loader on startup (load SQL templates from Cortex Extensions before starting the consumer loop)

### Architecture After Integration

```
Cortex Extension Stage (published skills)
    │  (read at startup)
    ▼
skill_loader.py (cached SQL templates)
    │
    ▼
Transaction arrives → enrichment.py (skill SQL: 4 profiling queries)
    → anomaly_detection.py (skill SQL: 5 rule-based checks → composite score)
    → agent.py (enrichment + anomaly results → LLM classification)
    → remediation + logging (skill SQL templates)
```

### Key Decisions
- SQL templates loaded once at startup, refreshable on demand
- Anomaly score computed by Python from rule-based SQL results (not LLM)
- LLM still makes the final fraud type classification, but now with anomaly evidence as input
- Fallback: if Cortex Extension stage is unreachable, agent works with embedded defaults
