## Integration Plan: Published Skills → FdsAgent Runtime

### Problem
The FdsAgent currently has:
- **Basic enrichment** (4 simple `SELECT *` queries in `enrichment.py`)
- **No rule-based anomaly detection** — everything delegated to a single LLM prompt
- **Embedded SQL** scattered across Python files

The published skills have much richer logic: behavioral profiling, 5 anomaly detection scripts with weighted scoring, structured classification prompts, and detailed remediation SQL.

### Approach: Load SQL from Cortex Extension Stage at Runtime

Read skill SQL templates from the Cortex Extension stage on startup. This means re-publishing skills automatically updates the agent's behavior — no Docker rebuild needed.

### Changes

1. **New `skill_loader.py`** — Fetches SQL templates from the Cortex Extension stage (`USER$NGARTOONIST.SKILL_SHARING.*`) at startup, caches them in memory. Falls back to bundled local copies if the stage is unreachable.

2. **Rewrite `enrichment.py`** — Replace the 4 basic queries with the skill SQL scripts:
   - `sender_profile.sql` → rich sender profile with account age
   - `sender_behavior.sql` → transaction stats, frequency, recipient patterns
   - `recipient_profile.sql` → bank details + distinct sender count
   - `recipient_inflow.sql` → inflow volume, distinct senders (mule detection)

3. **New `anomaly_detection.py`** — Runs the 5 anomaly detection scripts and computes a composite weighted score:
   - `velocity_check.sql` → HIGH_FREQUENCY_24H, NEW_RECIPIENT_BURST, AMOUNT_SPIKE
   - `time_evasion.sql` → UNUSUAL_HOURS, spacing patterns
   - `smurfing_check.sql` → structured small transactions
   - `rapid_onboarding.sql` → new account + large transaction
   - `circular_check.sql` → A→B→C→A money flow

4. **Update `agent.py`** — Wire the new modules into the pipeline:
   - Call enrichment → anomaly detection → classification (with enriched context + anomaly results in the prompt)
   - Use the weighted scoring from skills (not just LLM-generated scores)
   - Keep LLM for fraud type classification but ground it with rule-based signals
   - Use skill SQL for FRAUD_ANALYSIS_LOG and REMEDIATION_ACTIONS inserts

5. **Update `requirements.txt`** if any new dependencies needed (unlikely)
