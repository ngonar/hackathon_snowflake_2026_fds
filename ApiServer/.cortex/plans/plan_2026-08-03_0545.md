## Context

The app is a FastAPI remittance API. Currently, `app/queue.py` uses `pika` to publish transaction data to RabbitMQ after a transaction is created (called as a `BackgroundTask` from `app/routers/transactions.py:71`). The downstream fraud detection system consumes from the queue.

We'll replace this with: App INSERTs into a Snowflake table (`REMITTANCE_TRX`), a Stream captures new rows, and a Task periodically processes them (simulating the consumer side).

---

## Implementation Steps

### 1. Create Snowflake objects (SQL DDL)
- Create database `NGONAROID_FDS` and schema `PUBLIC`
- Create table `REMITTANCE_TRX` with columns matching the current message schema (id, reference_number, sender_id, recipient_id, source_currency, target_currency, source_amount, target_amount, exchange_rate, fee, status, created_at, updated_at)
- Create a Stream `REMITTANCE_TRX_STREAM` on the table (append-only)
- Create a Task `PROCESS_TRX_TASK` that runs every 1 minute, consuming from the stream and inserting into a `REMITTANCE_TRX_PROCESSED` table (fraud detection staging)

### 2. Replace `app/queue.py` with Snowflake publisher
- Rewrite `app/queue.py` → replace `pika` logic with `snowflake.connector` INSERT
- Function signature stays the same: `publish_transaction_message(transaction_data: dict)`
- Use parameterized INSERT with `snowflake.connector.connect()`

### 3. Update `app/config.py`
- Remove all `RABBITMQ_*` settings
- Add Snowflake connection settings: `SNOWFLAKE_ACCOUNT`, `SNOWFLAKE_USER`, `SNOWFLAKE_PASSWORD`, `SNOWFLAKE_WAREHOUSE`, `SNOWFLAKE_DATABASE`, `SNOWFLAKE_SCHEMA`

### 4. Update `requirements.txt`
- Remove `pika>=1.3.2`
- Add `snowflake-connector-python>=3.6.0`

### 5. Update `verify.py`
- Replace `verify_rabbitmq_message()` with `verify_snowflake_message()` that queries the `REMITTANCE_TRX` table for the expected reference number

### 6. No changes needed to `app/routers/transactions.py`
- The import and `background_tasks.add_task(publish_transaction_message, txn_dict)` call remains identical since only the internal implementation of `publish_transaction_message` changes.
